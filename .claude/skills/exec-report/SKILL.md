# 경영진 보고서 만들기

현장 보고서와 경영진 보고서는 다른 물건입니다. 현장 보고서는 "무슨 일이 있었나"를
빠짐없이 적지만, 경영진 보고서는 **"그래서 무엇을 결정해야 하나"**를 말합니다.
바쁜 대표이사는 제목만 넘겨봅니다. 제목만으로 상황이 읽혀야 합니다.

## 만들기 전에 정하는 세 가지

보고서를 쓰기 전에 데이터를 놓고 이 셋을 먼저 뽑습니다. 장표는 그 다음입니다.

1. **핵심 결론 한 줄** — 맥킨지·BCG 식으로. 변명이 아니라 팩트와 조치.
   *"9월 생산량 125만 개로 목표 105% 초과 달성, 수율 99%대 안정세 진입"*
2. **가장 중요한 시사점 세 가지** — 개조식. 각각 숫자를 하나씩 물고 있어야 합니다.
3. **요청사항** — 경영진이 승인·결정할 것. 없으면 보고할 이유도 약합니다.

## 네 가지 원칙

### 1. 액션 타이틀 (가장 중요)

제목에 결론을 넣습니다. 소재를 넣지 않습니다.

| | |
|---|---|
| ✗ | 9월 생산 현황 |
| ✓ | 9월 생산량 125만 개로 목표 5% 초과 달성, 수율 안정세 진입 |
| ✗ | 비가동 분석 |
| ✓ | 설비 결함으로 인한 가동 중단이 총 정지시간의 61% 점유, 상위 2개 요인 집중 관리 시 78% 개선 가능 |

- 두 줄까지. 첫 줄에 결과, 둘째 줄에 원인이나 함의.
- 제목 밑에는 영문 부제를 한 줄 답니다 (`Executive Summary : Key Performance Indicators`).
  격식이 생기고, 그 장표가 무슨 종류인지 바로 구분됩니다.
- 슬라이드 제목만 이어 읽었을 때 보고서 전체가 한 편의 이야기가 되어야 합니다.

### 2. 컬러의 통제 — 원 포인트 컬러

바탕은 무채색(딥 네이비 · 회색 · 흰색)으로 두고, **한 장에 강조는 한 곳만** 칠합니다.

- 잘한 것 → 에메랄드 그린 / 파랑
- 문제 → 빨강. **단, 미달 항목이 넷이어도 빨강은 가장 벌어진 하나에만.**
  전부 빨갛게 칠하면 시선이 나뉘어 아무 데도 꽂히지 않습니다.
- 나머지 미달 항목은 무채색으로 눕혀 둡니다.

### 3. 데이터 다이어트

- 로우 데이터를 표째 붙이지 않습니다. 대표이사는 소수점 둘째 자리가 아니라
  **추세(Trend)와 비율(Ratio)**이 궁금합니다.
- 가장 중요한 지표 **3~4개만** 거대한 숫자로 뽑습니다. 각 숫자 밑에는
  "목표 대비 +5.4%" 같은 델타 한 줄을 답니다. 숫자 하나만으로는 판단이 안 됩니다.
- 상세 표는 **별첨(Appendix)**으로 뺍니다.
- 축 눈금을 지우고 값을 데이터 포인트 옆에 직접 적으면 훨씬 깔끔합니다.

### 4. 픽토그램

글이 많아지는 '이슈 및 대응방안' 장표는 카테고리 아이콘을 제목 옆에 답니다.
읽기 전에 무슨 얘기인지 감이 옵니다.

외부 아이콘 파일(Flaticon 등)은 라이선스가 걸리고 파일도 무거워집니다.
**파워포인트 기본 도형(preset geometry)으로 그리면** 벡터라 깨지지 않고 용량도 0입니다.

| 용도 | prstGeom |
|---|---|
| 설비·고장 | `gear6` |
| 정비·주기 | `donut` |
| 자재·교체 | `cube` |
| 이상·급발생 | `lightningBolt` |
| 물류 | `flowChartInputOutput` |
| 안전·경고 | `triangle` |
| 증가/감소 | `upArrow` / `downArrow` |

## 워딩 — 명사형으로 끝맺기

불필요한 서술어를 빼고 명사로 끝냅니다.

| 현장 표현 | 경영진 표현 |
|---|---|
| 기계가 고장나서 안 돌아갑니다 | 설비 결함으로 인한 가동 중단 |
| 부품을 갈아야 해서 세웠습니다 | 소모품 교체 및 셋업 전환 |
| 원료가 안 와서 기다렸습니다 | 원부자재 수급 지연 |
| 정기 점검했습니다 | 계획 정비에 따른 계획 정지 |
| 막혀서 뚫었습니다 | 공정 이상에 따른 비계획 정지 |

- 한글 조사는 받침을 보고 고릅니다. "설비고장**가**"는 눈에 거슬립니다 → `josa()` 참고.
- 퍼센트 차이는 `%`가 아니라 **`%p`**입니다.

## 슬라이드 구성

이야기 흐름은 **배경 → 문제 → 분석 → 대안 → 실행계획 → 결론**입니다.

**주간 (표지 + 5장)** — 여섯 단계를 다섯 장에 담으려면 두 번 묶습니다.
요약을 배경에 합치고, 대안과 실행계획을 한 장으로.

| # | 성격 | 장표 |
|---|---|---|
| 1 | 배경 | Executive Summary — KPI 4개 + 시사점 3개 |
| 2 | 문제 | 계획 대비 달성 (bars + Action Required) |
| 3 | 분석 | 저해 요인 파레토 (bars + Insight) |
| 4 | 대안·실행 | 현안 과제 카드 3장 |
| 5 | 결론 | 결론 및 요청사항 |

**월간 (표지 + 9장 = 10장 이내)**
요약 / 추이 / 문제 / 저해요인 / 회수구조 / 생산성 / 현안과제 / 실행계획 / 결론 / 별첨

## 레이아웃 7종

`assets/deck.js`에 그대로 쓸 수 있는 코드가 있습니다.

| type | 언제 |
|---|---|
| `cover` | 표지 |
| `kpi` | 큰 숫자 3~4개 + 델타. 요약·결론 장표 |
| `bars` | 목표 대비 비교. 목표선(mark)과 원포인트 컬러 |
| `trend` | 추이. 값은 점 위에 직접 |
| `issues` | 현안 과제 카드 3장 (아이콘 + 우선순위 뱃지 + 현상/원인/대응) |
| `plan` | 실행계획 타임라인 (항목 / 담당 / 기한) |
| `table` | 별첨 상세 표 |

하단 배너 두 종류로 장표를 못박습니다.
- `Action Required` (빨강) — 무엇을 해야 하는가
- `Insight` (초록) — 이 그림이 말하는 것

## .pptx 만들기

`assets/deck.js`를 그대로 가져다 쓰면 됩니다. 라이브러리가 필요 없습니다 —
.pptx는 XML 몇 개를 담은 zip이라 직접 조립합니다.

```js
const slides = [
  { visual: { type: "cover", eyebrow: "MONTHLY REVIEW", title: "…", subtitle: "…", meta: ["…"] } },
  { kicker: "요약", accent: PT.green,
    title: "9월 생산량 125만 개로 목표 5% 초과 달성,\n수율 99%대 안정세 진입",
    subtitle: "Executive Summary : Key Performance Indicators",
    visual: { type: "kpi", items: [...] },
    points: [{ label: "생산", color: PT.green, text: "…" }] },
];
downloadPptx("월간보고.pptx", slides);
```

### 반드시 지킬 것

- 좌표는 1280×720(px) 기준으로 쓰고 `px()`가 EMU로 바꿉니다. 16:9는 12192000×6858000.
- 투명도를 줄 때 `<a:srgbClr>`를 열고 `<a:alpha>`를 넣은 뒤 **닫아야** 합니다.
  한 줄로 붙이다 `</a:srgbClr/>`가 나오면 파워포인트가 파일을 아예 못 엽니다.
- 액션 타이틀이 두 줄이면 부제 위치를 줄 수만큼 내립니다 (26pt ≈ 42px/줄).
  안 그러면 부제가 제목 둘째 줄에 겹칩니다.
- 값 텍스트에 `"5시간 50분 · 2건"`처럼 두 정보가 붙으면 줄을 나눠 넣습니다.
  한 줄로 밀면 글꼴에 따라 마지막 글자만 다음 줄로 떨어집니다.
- 한글은 `Malgun Gothic`을 `latin`·`ea`·`cs` 세 곳에 모두 지정합니다.

### 검증

만든 다음에는 반드시 열리는지 확인합니다. 눈으로 봐야 레이아웃이 겹친 걸 잡습니다.

```bash
soffice --headless --convert-to pdf --outdir out deck.pptx   # libreoffice-impress 필요
python3 -c "import pymupdf; [p.get_pixmap(dpi=62).save(f'out/{i+1}.png') for i,p in enumerate(pymupdf.open('out/deck.pdf'))]"
```

`python-pptx`로 파싱되는 것만으로는 부족합니다. LibreOffice가 더 엄격하고,
렌더링해서 봐야 글자 겹침·줄바꿈 사고가 보입니다.
